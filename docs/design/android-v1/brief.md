## 目的、平台和边界

Ferry 是 Pocket 3 素材的手机完整副本与飞牛 SMB 上传工具。Android 最终使用 Kotlin／Jetpack Compose 原生 UI；文字、导航、表单和控件必须由原生代码实现，不能把本目录的位图交付为可用界面。当前没有 App 实现或运行验证。

先读取来源，在应用私有持久目录完成完整副本和摘要，再从完整副本上传；远端内容读回校验通过后才能显示“已完成”。保留相机原文件；同名目标不能被覆盖。App 在前台运行，离开前台保留状态并等待下次打开；人工暂停只能由用户恢复。首期目标为飞牛 SMB，网络可明确选局域网或内嵌 tsnet，不自动回退；默认只用 Wi-Fi 上传。不展示 OpenDAL、网盘或自动接入功能。

M0 probe 只展示受控服务和测试素材诊断，不能声称 Pocket USB 或真实飞牛已验收。M1 示例使用 `SOURCE-DEMO` 和 `NAS-DEMO` 等虚构逻辑名称；“可访问”“已完成”、文件名、摘要、数量、大小、进度、时间和容量全部是设计 fixture，不能作为连接或传输证据。不得使用真实凭据、节点、私人素材或网络状态。

## 必需的完整屏幕与状态

| 概念 ID | surface／状态 | 必须解释的信息和行为 |
| --- | --- | --- |
| A01 | M1 任务主屏：活跃任务 | 来源可用性、待导入／待上传、当前导入／上传／校验阶段、真实字节形式进度、完整副本占用；可暂停；人工暂停条目；已完成条目明确远端 SHA-256 已验证 |
| A02 | M0 诊断 probe | 受控测试服务、网络路径、测试来源只读、Android／Go 桥接状态、非稀疏构造文件字节和参考摘要、导入／上传／读回阶段，取消按钮与失败边界；“Pocket USB 未验证” |
| A03 | M1 来源：授权入口／失效 | 选择系统目录、只读授权、逻辑来源名和可用性；重新授权或重新选择；明确不改名、不写入、不删除原文件；来源不可用时导入等待、完整手机副本可独立上传 |
| A04 | M1 目标：首次配置 | 飞牛 SMB 配置名、主机占位、共享／根目录、NAS 账号用户名输入、密码保护输入；局域网／应用内 Tailscale 显式选项、浏览器交互登录入口、底层 Wi-Fi 条件、连接测试与保存；连接状态不冒充文件已验证 |
| A05 | M1 规则：配置与匹配预览 | 来源／目标引用、目录边界、扩展名允许与排除、first_match／排除优先、含完整 `{sha256}` 的路径模板；缺失时间为 `unknown-date`；未知摘要时目标待内容确定；新规则不改已有任务位置 |
| A06 | M1 任务详情：等待空间 | 文件需求与剩余空间、已完整导入副本保留、不完整文件不能上传；释放空间后继续；不自动清除未完成副本、不流式直传；人工暂停入口 |
| A07 | M1 任务详情：校验失败／可恢复中断 | 远端读回与本地摘要不一致，未完成；手机完整副本保留；目标与网络、阶段记录、文件级重试和人工暂停；同名目标不覆盖 |
| A08 | M1 任务主屏：首次配置空态 | 没有任务；来源、目标、规则的三个初始化步骤；配置完成并且来源可用时，前台打开 App 检查并执行；离开停止，原文件保留 |
| A09 | M1 任务详情：人工暂停 | 打开 App 或网络恢复仍保持暂停，完整副本保留、校验未完成；由用户明确恢复；不承诺字节范围续传 |
| A10 | M1 任务详情：读回校验中 | 只有一个活跃 SMB 操作；已上传不等于完成；读回字节进度、等待内容一致、可暂停且副本保留 |
| A11 | M0 诊断 probe：初始未运行 | 受控服务配置入口、建立会话、构造测试文件或选择只读目录、桥接检查与未满足前置条件时禁用开始传输 |

任务／来源／目标／规则四个导航标签在 M1 各完整页面保持一致。M0 为单独诊断 surface，不误装成 M1 功能导航。每张图是独立可读竖屏，不拼成压缩板。若文字、按钮、状态或主要内容模糊／裁切，重新生成该状态；不得用 SVG、HTML、假截图或后处理伪造出图。

M1 产品页使用用户可识别的“应用内 Tailscale”；M0 技术诊断可以使用“内嵌 tsnet”。图内“设计示例，非运行证据”是 review-only 注释，未来原生 UI 不实现此句。名称、数值、路径和状态实例是动态 fixture，不是固定生产数据；“已完成须远端内容校验通过”“人工暂停须手动恢复”“来源原文件保留”等真实状态与行为文案仍是产品要求。A01 的网络术语已由 Image Gen 定向修订，当前选定版本为 v3；旧版本的原始工具缓存与 prompt／hash／修正记录保留，旧稿工作区 PNG 已清理。

当前约 6–7 张的初始建议扩展到 11 个完整候选状态：首次配置空态、人工暂停恢复、读回校验和 M0 初始操作独立成图。只允许单个导入与单个网络任务并行；读回与上传属于同一受限 SMB 操作。A01 v1／v2 中同时上传与另一条读回的 fixture 逻辑错误已由 Image Gen v3 纠正；v1／v2 标为 superseded，不能作为当前候选依据，其原始工具缓存与记录保留。A10 是独立状态示例，不与 A01 同时运行。

## 概念设计方向

专业、通透的媒体备份工具：真白背景、克制的单一强调色、清晰中文层级和开放列表；让当前操作阶段成为首要焦点。避免营销 hero、嵌套卡片、默认 card grid、装饰徽章、编造的指标和无功能意义的插画。这个方向是生成概念的约束，不是生产 tokens 或组件几何。

## 工具、验证和停止条件

使用 `build-web-apps:frontend-app-builder` 的完整 surface／Concept Review Mode 和 `imagegen` 的默认 built-in 工具。先生成 A01，然后以经 `view_image` 检查的 A01 原图作为其他页面的风格参考；每张单独记录实际 prompt、源路径、保存路径、文件 SHA-256、原始像素尺寸、文案检查和异常。

本轮只做生成与静态图检查：文案、导航、流程、阶段、安全边界、可读性和裁切。Browser／Playwright、native 实现截图、fidelity 对照、交互、APK、USB、SMB 和设备验收全部未运行，不可标为通过。

若 built-in 工具不可用或失败，立即向 root 报具体错误，保留 brief，不改用 CLI／API。若出现实质文字错误或假完成语义，迭代后复查；无法纠正则标为未满足、保留阻塞，不能宣称概念完整。所有选定图仍是候选设计，待用户逐一接受；接受前不提取生产 tokens、不写详细 UI 实施计划、不开始 App 实现。
