# M1：Android 可用前台基础版与 Pocket 完整链路

状态：**Android 优先范围提案；M0-V01–V05 通过并获用户明确批准 M1 后才能实现。** 本阶段只交付 Android `on_open` 前台基础版和真实 Pocket 3 → Pixel 6 Pro → fnOS 主链路；没有 iOS 工程、macOS、iOS 签名或双平台回归前提。完整故障注入由 M2 承接，第二网络路径只作补充证据。

## 任务与实际产物

交付 Kotlin／Compose Android App：配置来源／目标／规则，打开 App 后只读导入完整手机副本，经至少一条明确选择的网络路径上传 SMB，读回 SHA-256 后无覆盖提交，持久化任务与人工暂停，离开前台停止新操作／返回恢复系统等待。任务区分导入／上传／校验／等待／失败，无内容证据不能完成。

交付 Actions 真 APK、完整源码 SHA／版本／ABI／SHA-256、安装记录和 Pixel／Pocket／fnOS 实测报告。自动接入／FGS 在 M2，M1 不显示可用自动模式开关。第二网络路径、完整故障矩阵和视觉 fidelity 是补充或后续结果；iOS bridge／工程／UI／保护存储留 M3，Go 只保留 Android 所需正常边界与规则向量。

## 前置决定与功能契约

Apache-2.0 已确认。Android applicationId 建议 `io.github.ghostflying.ferry`，probe 后缀 `.probe`；默认 `minSdk 29`（Android 10），不处理 Android 9 及更低版本。允许较新的 `compileSdk`／`targetSdk`，但实际 API 号和 ABI 由实现开始前锁定的 devcontainer 稳定工具链确定并记录，不使用日期相关的 `latest`。M0 结束用户 gate 需确认 Pocket／Pixel／fnOS 的实际操作条件、受控共享与选择的第一网络路径。

P1 冻结当前 Android 实际需要的契约，不冻结未实现 iOS 接口或视觉细节：

- 配置 v1／字段校验／错误定位；占位授权和凭据不能当作可用连接。
- `first_match`、排除优先、大小写、目录边界、时区／缺失时间、长名／非法路径与完整哈希；未知哈希仅待内容确定预览，完整导入后才冻结路径。
- Room 事务、不可变目标 revision、操作意图／阶段／人工暂停／系统等待；外部操作前落意图，确认提交后落完成。
- Android 原生 URI／Context 不进 Go；文件路径和小消息跨 bridge；`net.Conn` 留同一 Go runtime 内；操作使用版本／ID／结构错误／回调线程／64 位计数／取消完成／迟到事件隔离。
- source／spool／repository／transport／执行协调器的输入输出与单 owner。凭据和节点状态按 Android Keystore 保护；不预制 iOS 回调／平台服务层。

## 容器内与外部验收边界

M1 的 Android／Go／bridge 构建、单测、静态检查、规则向量、APK 生成和产物哈希
均在固定 devcontainer 内执行；不能使用宿主 JDK／SDK／NDK／Go／Gradle 缓存或
工具链结果。宿主只负责启动容器、保存脱敏产物，以及在需要时显式连接 ADB。
Dora 使用容器构建出的 APK，ADB 连接本身不构成构建证据。

Pixel／Pocket／fnOS、USB／SAF 授权、第一网络路径、SMB 服务、远端读回、暂停／
恢复和清理是设备或服务外部动作，分别记录环境与证据；AV01–AV03、AV12 的构建／
检查部分在容器内，AV04–AV11 的实体设备、服务与 native 截图动作在容器外部（其
测试代码仍须在容器内构建／检查）。缺容器运行时只将依赖它的构建／检查标为
`BLOCKED`，不回退到宿主环境；该边界不把低概率故障矩阵或新的发布渠道要求提前
加入 M1。

## 数据完整性与运行行为

完整副本存私有持久目录并排除备份；partial、完整、保留副本与并发预留一起核算空间。未知 size 运行时上限、单文件超过 max_bytes 等待空间，不改直传；拔线或源变化不能标完整。版本信息不可靠时重新读哈希，说明重复扫描可能占用导入空间。远端读回 SHA-256 通过后才能完成和按策略释放手机副本。

SMB 排他临时创建、flush／读回、服务端 no-replace；同内容复用必须有内容证据，不同内容不覆盖。提交后记录前 kill 的完整故障矩阵移 M2；M1 只要求基本取消／`on_open` 对账不误完成并保留副本。只清本任务临时对象，凭据和节点状态不进日志／仓库。

离开前台停止新操作并保存；返回恢复系统等待，人工暂停保持。SAF 重新挂载失效要求重选，并在结果中区分 `PASS`／`FAIL`／`BLOCKED`／`NOT_RUN`。Dora 设备如使用必须按 M0 新 session 隔离与 finally cleanup，普通 provider 不代替 Pocket USB。

## 可判定验收

历史双平台 Vxx 保留在旧 SHA，不继承通过。M1 的核心 gate 是 AV01–AV04、AV06 与 AV09；AV05 容量边界为 `OPTIONAL`／`CONDITIONAL` 附加证据，不阻塞核心主链路；AV10 是安全与 lease 操作条件，AV07／AV11 为补充或独立 UI，AV08 的完整故障注入移 M2，AV12 是交付报告检查项。源只读、完整副本、远端 SHA-256、no-replace 和人工暂停仍属于核心边界。每行绑定最终 SHA／APK 哈希、环境、输入、动作、预期／实际及 `PASS`／`FAIL`／`BLOCKED`／`NOT_RUN`。

## 独立 review、停止与用户 gate

M1 不要求每个 task 各自重复 plan review：本文件是 M1 的一份 execution plan，在 M1 开工前执行一次独立 plan review；实现后由非作者做最终 integrated/device review，分别复核主链路、内容证据、源只读／副本、人工暂停和安全清理。这个最终 review 不是第二次 plan review。UI 接受与 milestone 批准分别记录，M1-UI 不替代主链路结果。

缺 Pocket／Pixel／fnOS、第一网络路径或有效设备操作条件只暂停相应依赖；不使用 Dora 模拟替代指定 USB。主链路内容不一致、源被修改、无远端读回、无 no-replace 或人工暂停误恢复为 `FAIL`。第二路径、完整故障矩阵、视觉未测如实标为 `OPTIONAL`／`DEFERRED`／`NOT_RUN`，不伪造通过。

提交 APK／hash／CI／SHA、主链路逐项验收、UI 独立结果、限制和 M2 计划给用户；只有用户明确批准 M2，才能开始自动模式、完整故障注入与 Android 发行准备。
