# M1 Android contract v1

This contract is the Android-only boundary between Kotlin-owned file handles,
durable state and the Go core. It does not expose Android `Context`, `Uri`,
service objects or lifecycle callbacks to Go.

## Configuration

`Config` is version `1` and requires `source_name`, `target_name`,
`target_address`, `time_zone` and unique rule IDs. Empty or malformed fields
are rejected before source or network work. Credentials are references to
Android protected storage; they are never serialized into this contract or
logs.

## Rule behavior

Rules are evaluated by exclusion priority, then first matching include rule.
Unmatched entries are excluded. Matching uses normalized slash-separated
relative paths, case-insensitive extensions, optional prefix and optional
maximum byte count. Unknown content hashes may be previewed but cannot freeze
the final remote path or report completion.

## Operation state

Every external operation records its operation ID, immutable configuration
revision and intent before work. Phases are `imported`, `uploading`,
`verifying`, `waiting`, `paused`, `failed` and `completed`. A manually paused
operation remains paused across `on_open`; returning to the foreground can
resume system-waiting work only.

## Completion

The source is read-only. A private complete copy remains until the remote
temporary object is flushed, read back and SHA-256 matches the source. The
SMB adapter creates the final object with a server-side exclusive create
(`O_EXCL`); an existing destination is left untouched and the operation fails.
That no-replace result is recorded before the operation becomes `completed`.
The M1 adapter does not claim an atomic temp-to-final rename: crash-time final
partial recovery and the complete kill matrix are M2 work. A cancelled or
interrupted operation cannot report completion while the process is running.
